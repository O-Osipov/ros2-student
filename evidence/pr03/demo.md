# ПР03: поза, таймер и исправление имени

Опыт выполнен 25 сентября 2026 в ROS 2 Lyrical / Ubuntu 26.04, Python 3.14.4.
Образ зафиксирован в `.gitverse/workflows/pr03.yml`. Настоящий turtlesim запущен
с `QT_QPA_PLATFORM=offscreen`: результаты подтверждены сообщениями и координатами,
видимое окно не проверялось. Последовательность и сырые выводы — в `tests.txt`.

## Что делает программа

- `rclpy.init` создаёт контекст ROS и обрабатывает ROS-аргументы, включая remap.
- `Patrol` регистрирует подписку, издателя и таймер; `latest_pose` сначала None.
- `spin` обслуживает события через executor. Callback подписки сохраняет Pose,
  callback таймера берёт последнее состояние и публикует Twist каждые 0,1 с.
- Чистая `choose_command` возвращает `(0, 0)` без позы и `(0.5, 0.3)` после неё.
  Она не изменяет Pose. Контроль устаревания позы в обязательную часть не входит.
- `Ctrl+C` завершает ожидание; нода освобождает ресурсы. Это не команда торможения:
  turtlesim останавливается позже по собственному watchdog. Реальный робот
  потребует своей логики безопасной остановки.

## Проверка до первого сообщения

До запуска turtlesim запущен установленный executable:

```bash
ros2 run patrol patrol --ros-args -r cmd_vel:=/turtle1/cmd_vel
```

Наблюдатель получил пять нулевых Twist. Затем patrol остановлен, появилась
черепаха через `ros2 launch turtle_bringup sim.launch.py`. Тип позы проверен
`ros2 topic type /turtle1/pose`: `turtlesim_msgs/msg/Pose`.

## Дефект и исправление

Запуск `ros2 run patrol patrol` создаёт издателя `/cmd_vel`.
`ros2 node info /patrol` подтверждает подписку `/turtle1/pose`, но
`ros2 topic info /cmd_vel --verbose` показывает 1 издателя и 0 подписчиков.
У `/turtle1/cmd_vel` в этот момент 0 издателей и 1 подписчик turtlesim.
Координаты до и после ожидания совпали: `(5.54444456, 5.54444456, 0.0)`.

Причина: относительное имя `cmd_vel` в корневом namespace стало `/cmd_vel`,
а симулятор подписан на другое полное имя `/turtle1/cmd_vel`.
Одинаковый тип сообщения не соединяет разные имена.

Остановлен прежний patrol, изменён только аргумент запуска:

```bash
ros2 run patrol patrol --ros-args -r cmd_vel:=/turtle1/cmd_vel
ros2 topic info /turtle1/cmd_vel --verbose
ros2 topic hz /turtle1/cmd_vel
```

До подключения измерителей найден один издатель и один подписчик. Измерение
за 10,015 с дало 100 сообщений и 10,000 Гц; все команды `(0.5, 0.3)`.
Поза изменилась до `(4.20320797, 8.20588493, -2.21278524)`. Измеритель
временно добавляет подписку; на ошибочный `/cmd_vel` он не подписывается.

После SIGINT patrol завершился с кодом 0, издатель исчез. Через ожидание
watchdog скорости стали нулевыми, поза перестала меняться. Затем закрыт launch.

## Тесты и повторение

`python3 -m pytest -q src/patrol/test`: 4 passed. Три случая чистой функции
и один тест настоящего ROS-обмена: нулевая команда, получение и обновление Pose,
команда после первой позы, неизменность остальных полей Twist, один издатель.
Унаследованный `turtle_bringup`: 4 passed, 1 skipped (copyright-пропуск генератора).
Его XML-линтер получает официальную схему по сети; это часть среды CI.

`python3 scripts/check_pr03.py` повторяет весь опыт после сборки и source.
В stdout выводятся CLI, частота, координаты и завершение. Он запускает процессы
в выделенном домене, поэтому старые turtlesim/patrol/teleop нужно остановить.
Аргументы и подготовка workspace приведены в корневом README.

Числа выше относятся к первому успешному полному прогону в `tests.txt`.
Последующая локальная проверка workflow может дать немного другие координаты:
она заново запускает симулятор и проверяет те же условия, а не равенство чисел.
Удалённый GitVerse run этим отчётом не заявляется.

с 2 до 4 и 8 с. Неизвестный топик/нода и неполный граф допускают повтор;
